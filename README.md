# SKELLFORGE

**SkellForge v0.1** is Skelly's internal developer tool for creating Windows-only
VST3 audio plugins that share SkellCore. It does not replace JUCE, and it is
not a visual drag-and-drop editor yet.

**[SkellCore](https://github.com/skellyruno/skellcore-vst-template)** owns the
portable DSP engines, shared UI widgets, skull/theme infrastructure and opt-in
plugin-to-plugin integrations. **SkellForge** owns project creation, identity
checks, manifests, build orchestration, VST3 packaging and, later, visual design.
Existing production plugins are not modified by installing this tool.

## Get started

Prerequisite: Python 3.10+ and a clone of this repository. No pip dependencies.

```powershell
python -m skellforge doctor
python -m skellforge new "Skell Pulse" ../skell-pulse --code SF01
python -m skellforge validate ../skell-pulse
python -m skellforge audit ../skell-pulse --json
```

Choose a unique four-character product code for every plugin; Forge checks
against the 2026-11-11 SkellWorld catalog snapshot, but **this is not an
exhaustive live registry**. Verify identities before distributing a plugin.

To build on Windows x64, install Visual Studio Desktop development with C++,
CMake and Git. Generator defaults to pinned JUCE 8.0.12 and pinned SkellCore
commit; for local/offline dependencies use explicit paths:

```powershell
python -m skellforge build ../skell-pulse --juce-path C:/JUCE --core-path C:/src/skellcore-vst-template
python -m skellforge package ../skell-pulse
```

`--core-path` accepts either the SkellCore repository root (containing
`SkellCore/CMakeLists.txt`) or the `SkellCore` library folder itself. A non-empty local
`JUCE_PATH`/`SKELLCORE_PATH` that does not contain the library fails the configure step
with a clear message instead of silently downloading one (an empty value, or not passing
the option, means "download the pinned dependency").

Product names must be 2-80 characters (letters, digits, spaces, `_`, `-`), start with a
letter, not end with a space, contain at most 50 letters/digits in total (they form the
stable SkellWorld ID), and not be a reserved Windows file name such as `Aux` or `Con`.

The plugin generated by Forge also includes its own Windows VST3 GitHub Actions
workflow, which can build a downloadable VST3 without your local machine.

## Available today

- **Plugin generator**: buildable JUCE C++17 VST3 starter, mono/stereo gain
  effect (0 dB default), smoothed automation, state save/restore, resizable UI
- **SkellCore integration**: pin immutable commit, optionally use local checkout,
  shared DSP, StudioUI hardware-style knobs and skull-click appearance
- **Identity protection**: VST3 code collision checks, non-overwrite generation,
  stable bundle/manufacturer/World IDs, manifest validation, and a conservative
  parameter-ID guard: `validate` fails if an ID listed in `skellforge.json` no longer
  appears as a `"string"` in any source file (renaming a released ID breaks saved
  projects and automation). It catches an ID that was renamed or removed everywhere;
  it cannot prove an ID is still *declared*, so moving it into a constant is fine
- **Read-only migration audit**: inspect existing plugin CMake/parameter IDs (modern
  `juce::ParameterID` and legacy string-ID constructors, comments ignored), warn on
  standalone builds (including multi-line `FORMATS`) or unpinned shared core, report
  JSON without changing plugins
- **Build/packaging**: Windows x64 CMake build command, exact-one-bundle packaging
  (Release bundle preferred over stale Debug output), checks for nested VST3 binary
  and ZIP integrity, no partial ZIP left behind on failure
- **Automated tests**: generator, reserved IDs, tampering, packaging, error paths
  on Linux and Windows; separate native Windows VST3 smoke-build workflow

## Repository organization

- `skellforge/` - Python standard-library command-line application
- `templates/` - CMake, C++ source, docs and Windows CI for generated plugins
- `config/known_codes.json` - known existing plugin identifiers (snapshot)
- `tests/` - generator and package regression tests
- `docs/ROADMAP.md` - phased work toward a visual drag-and-drop Forge

## Limits

This is a **development milestone**, not a validated shipping-grade DSP framework.
The existing SkellCore skull-key symbol is temporary until the final approved
Skelly skull is shared. Generated plugin project IDs must be locked before
shipping; a standalone build is intentionally NOT created.

A successful CI compile does not prove FL Studio compatibility, CPU performance,
real-time DSP safety or actual audio quality. Test in a DAW before release.
Dependencies carry their respective licenses; review JUCE/Steinberg and third-party
terms before distributing SkellForge as a public code generator.

Run the tests:

```sh
python -m unittest discover -s tests -v
```
